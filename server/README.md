# FX Sentinel — API 서버 (파일럿 전 단계)

데모 HTML 위에 **실서비스 요건**을 얹는 계층입니다. 판정 권위를 브라우저에서 서버로 옮깁니다.

> **데모는 그대로입니다.** `FX_Sentinel_demo_ui.html` 은 이 서버 없이도 단일 파일로 동작하며,
> 이 서버 작업으로 한 줄도 바뀌지 않았습니다. 기존 UI 스모크 테스트도 그대로 통과합니다.

---

## 1. 무엇이 진짜이고 무엇이 아닌가

이 구분이 이 프로젝트에서 가장 중요합니다. 섞이면 정직성이라는 유일한 자산이 사라집니다.

### ✅ 실제로 구현된 것

| 항목 | 내용 |
|---|---|
| **서버 권위 판정** | 화면이 계산한 BBP·자격을 **받지 않는다.** 입력만 받고 서버가 다시 계산·판정 |
| **OIDC/JWT 인증** | 서명·`iss`·`aud`·`exp` 검증. 서명 틀린 토큰은 통과 불가 |
| **서버 RBAC** | customer / rm / branch / compliance / admin. 화면 숨김이 아니라 **서버 거부(403)** |
| **해시체인 감사로그** | append-only. 각 레코드가 이전 해시를 품어 사후 변경이 탐지됨 |
| **제재 스크리닝** | OFAC SDN · UN · EU **공개 리스트 실수집** + 정규화·퍼지매칭 |
| **입력 검증** | 통화 화이트리스트(CNY 차단), 범위 검증 — 화면만 막고 API 가 열리는 일 없음 |
| **상품 마스터 외부화** | 상품 16건이 `catalog/products.yaml` 로 분리. HTML 편집 없이 문안 수정 |
| **분할(레이어드) 헤지** | 목표비율을 25% 단위로 나눠 체결하는 일정 산출 |
| **포트폴리오 집계** | 다건 합산·자연헤지(네팅)·만기 캘린더. 상계는 같은 통화·같은 만기 구간만 |
| **알림 규칙 엔진** | 만기·BBP·국면·미헤지 구독 + 쿨다운(알림 피로 방지) |
| **라이프사이클 상태머신** | 접수→서류→한도→체결→만기/롤오버. 실수요 초과 헤지·해지 차단 |
| **이중구현 방어** | 데모 JS 와 서버 Python 을 실제 Chrome 으로 전수 대조 |

### ❌ 연동되지 않은 것 — 가짜로 채우지 않았습니다

`GET /v1/integrations` 가 이 목록을 그대로 응답합니다.

| 시스템 | 막힌 이유 | 연동 전 대체 |
|---|---|---|
| 기업뱅킹 SSO | KB 가 OIDC 클라이언트를 발급해야 함 | 자체 IdP — 프로토콜만 실물, **KB 신원 아님** |
| KB 원장·여신 한도 | 코어뱅킹 조회 권한·전용망 | 고객 신고값 + "RM 확인 필요" 강등 표시 |
| KB 고시환율 | 고시 테이블 조회 계약 | 기준일 스냅샷(고시환율 아님 명시) |
| KB 상품 요율·한도 | 상품/약관 DB·가격엔진 | 후보 제시까지만, 요율은 RM 견적 |
| 관세청 UNIPASS | 사업자 등록·이용신청 | 증빙 수기 확정 |
| RM 업무함/CRM | 행내 시스템 연동 | 서버 내 티켓 — **실제 RM 에게 전달되지 않음**(응답에 명시) |

이것들은 코딩 속도의 문제가 아니라 계약·보안심사·망분리의 문제라 외부에서 앞당길 수 없습니다.
어댑터는 `NotImplementedError` 를 던지며, 호출부가 이를 "미확인"으로 강등해 응답과 감사로그에 남깁니다.

## 1.5 데모 두 판 (V1 / V2)

| 판 | 파일 | 성격 |
|---|---|---|
| **V1** | `FX_Sentinel_demo_ui.html` | **예선 제출물.** 서버 없이 파일 단독 동작. 이 서버 작업으로 기능 변경 없음 |
| **V2** | `FX_Sentinel_demo_ui_server.html` | **생성물.** V1 + 서버 재검증 패널(④ 심사 자료 탭) |

```bash
python scripts/build_server_demo.py            # V1 → V2 생성
python scripts/build_server_demo.py --check    # V2 가 최신인지 검사 (테스트가 강제)
```

> **V1 이 마스터, V2 는 생성물입니다.** 1MB 짜리 HTML 두 벌을 손으로 유지하면 반드시 갈라집니다.
> V1 을 고치면 V2 를 다시 만드십시오. 빌드는 V1 을 **읽기만** 하며, 테스트가 V1 오염을 검사합니다.

### V2 가 보여주는 것

④ 심사 자료 탭의 "서버 재검증" 패널에서 같은 입력을 실제 API 로 보내 결과를 대조합니다.

```
화면 계산 BBP     64.3%
서버 재판정 BBP    64.3%
일치 여부         일치 — 서버가 같은 결론
감사 ID           ac603aa2c932...
서버 차단         여신 한도 미확인 — KB 원장·여신 미연동
```

콘솔에서 클라이언트 계산을 위조하면(`window.bbpOf = () => 0.05`) 이렇게 잡힙니다:

```
화면 계산 BBP     5%
서버 재판정 BBP    64.3%
일치 여부         불일치 — 서버 값이 정답
```

**V2 도 서버 없이 단독 동작합니다** — 서버가 없으면 이 패널만 "연결하지 못했습니다"로 남고
나머지 화면은 V1 과 똑같습니다. V1·V2 모두 UI 스모크 328개를 통과합니다.

```bash
FXS_TARGET=FX_Sentinel_demo_ui_server.html python ../tests/ui_smoke_test.py
```

### V2 를 서버에 붙이려면 (CORS)

데모를 `file://` 로 열면 브라우저가 보내는 Origin 이 `null` 입니다. 서버가 이를 허용해야 합니다.

```bash
export DEV_JWT_SECRET=dev-only-secret
export ALLOW_ORIGINS=null            # file:// 로 열 때. 호스팅하면 그 주소를 넣으십시오
uvicorn app.main:app --port 8000

python scripts/dev_token.py --role rm    # 패널에 붙여넣을 토큰
```

`ALLOW_ORIGINS` 를 설정하지 않으면 브라우저가 응답을 버리고 V2 는 폴백합니다(실측 확인).

## 2. 실행

```bash
cd temp/KB/server
pip install -r requirements.txt

# 개발용 대칭키 모드 (운영 금지)
export DEV_JWT_SECRET=dev-only-secret        # Windows PowerShell: $env:DEV_JWT_SECRET="dev-only-secret"
uvicorn app.main:app --reload
```

문서: http://127.0.0.1:8000/docs · 헬스: `/health` · 경계 공개: `/v1/integrations`

## 3.5 상품 마스터 · 분할 헤지

### 상품 마스터 (`catalog/products.yaml`)

상품 문안이 데모 HTML 의 JS 배열에 박혀 있어, 상품 담당자가 한 줄을 고치려면 4,000행짜리
HTML 의 따옴표 사이를 편집해야 했습니다. 이제 **YAML 이 마스터**입니다.

```bash
python scripts/sync_demo_products.py --check   # YAML ↔ 데모 일치 검사 (테스트가 강제)
python scripts/sync_demo_products.py --write   # YAML 기준으로 데모 JS 블록 재생성
```

데모는 단일 파일이라 런타임에 YAML 을 읽을 수 없으므로 같은 내용이 두 곳에 존재합니다.
`--check` 를 테스트에 걸어 갈라지는 즉시 죽게 했고, `--write` 로 YAML→HTML 단방향 생성을
제공합니다. **요율·한도는 카탈로그에 넣지 않습니다**(KB 상품 DB 미연동 — 지어내지 않음).
자격 조건도 넣지 않습니다. 카탈로그는 `eligibility_key` 만 들고, 판정은 `elig.py` 가 합니다.

### 분할(레이어드) 헤지

`/v1/assess` 응답의 `hedge_schedule` 이 목표비율을 25% 단위로 나눠 체결하는 일정을 냅니다.

```
BBP 64.3% · 목표 50%
  1회차  25%  100,000 USD  D+0    (만기까지 63영업일)
  2회차  25%  100,000 USD  D+32   (만기까지 31영업일)
  미헤지 50%
```

> **분할하는 것은 비율이 아니라 실행 시점입니다.**
> 처음에는 LossAlert 를 25% 단위로 재매핑해 "더 정밀한 목표비율"을 내려 했는데,
> LossAlert=0.15 에서 **기존 엔진은 50% 헤지·새 로직은 0% 헤지**를 권고하는 충돌이 생겼습니다.
> 같은 입력에 정반대 권고입니다. 비율 밴드(0/50/100 을 25 로 쪼갤지)는 캘리브레이션된
> **KB 의 정책 결정**이지 도구가 임의로 바꿀 사안이 아니라고 판단해, 목표비율은 엔진 값을
> 그대로 쓰고 실행만 분할합니다. `test_target_ratio_is_never_altered` 가 이 회귀를 막습니다.

분할은 **기대손익을 개선하지 않습니다** — 체결 타이밍 집중을 분산할 뿐입니다.
환율을 예측하지 않으므로 "분할하면 더 유리한 환율"은 주장할 수 없고, 테스트가 그 문구를 금지합니다.

## 4. 제재 리스트 수집

```bash
python scripts/fetch_sanctions.py            # OFAC + UN + EU
python scripts/fetch_sanctions.py --sample   # 네트워크 없이 테스트용 가상 샘플
```

실측 결과 (2026-07-19):

| 리스트 | 결과 |
|---|---|
| OFAC SDN | ✅ **19,169건** |
| UN 안보리 통합 | ✅ **1,010건** |
| EU 통합 | ❌ **403 Forbidden** — 무인증 공개가 아니게 바뀜. EU FSD 이용자 토큰 신청 필요 |

EU 는 적재되지 않은 상태이며, 그 사실이 `lists_version` 응답에 그대로 드러납니다.
없는 리스트를 있는 척하지 않습니다.

실데이터 동작 확인:

```
ROSNEFT                  → OPEN JOINT-STOCK COMPANY ROSNEFT OIL COM   100.0  [OFAC_SDN]
Sberbank of Russia PJSC  → PUBLIC JOINT STOCK COMPANY SBERBANK OF R    87.8  [OFAC_SDN]
Wagner Group             → PRIVATE MILITARY COMPANY 'WAGNER'          100.0  [OFAC_SDN]
한빛정밀 주식회사          → (미탐)
Tokyo Precision KK       → (미탐)
```

캐시가 없으면 서버는 **"조회 불가 — 준법 수기 확인 필요"** 로 응답합니다. 조용히 통과시키지 않습니다.

리스트 미탐을 **"정상"이라고 쓰지 않습니다.** 표기 차이·간접 소유(OFAC 50% 규칙)·시점 차이로
미탐이 발생할 수 있고, 미탐은 결백의 증명이 아니기 때문입니다.

### 이중구현을 어떻게 막는가

같은 규칙이 JS 와 Python 두 곳에 있으면 **반드시 갈라집니다.** 그래서 갈라지는 즉시 죽게 만들었습니다.

- **ELIG**: 실제 Chrome 으로 데모의 `eligible()`·`denyReason()` 을 128조합 실행해 Python 과 대조
- **BBP**: 닫힌형이므로 `1e-6` 허용오차로 대조 — 차이가 나면 표본오차가 아니라 수식 drift
- **ES**: 몬테카를로라 JS(12,000표본)와 정확히 같을 수 없음.
  JS 대조는 **총체적 drift 만** 잡고(기준값 자체가 노이즈), Python 수식은 **수치적분**으로 따로 검증.
  실측 기준 5% 스케일 오차가 4.5~40σ 로 잡힙니다.

> ES 수치적분 주석: 수입 방향의 ES 는 수학적으로 발산합니다(Student-t 다항꼬리 × `exp`).
> 다만 발산이 지배하려면 `t ≈ 150`(P ≈ 1e-12)이 필요해 실무 표본수에서는 나타나지 않으며,
> 절단점을 30→240 으로 바꿔도 값이 45.5488→45.5511 로 불변입니다. 데모 수치는 정상입니다.

## 5.5 포트폴리오 네팅 — 데모보다 엄격한 이유

데모 대시보드는 **만기를 무시하고** 수출 USD 총액과 수입 USD 총액을 상계합니다.
3월에 받을 달러로 9월 지급을 막을 수는 있지만, 그 사이 6개월치 환위험과 자금부담이 남습니다.

서버는 **(통화 × 만기버킷)** 안에서만 상계하고, 버킷을 넘는 상계 가능분은 `timing_mismatch` 로
분리해 표시합니다. 두 숫자를 하나로 뭉개지 않습니다.

```
수출 500,000 USD (D+10, 0-1M) · 수입 500,000 USD (D+126, 3-6M)
  offset_within_bucket : 0          ← 상계 안 됨
  net_exposure         : 1,000,000
  timing_mismatch      : 500,000    ← 만기를 무시하면 상계되는 것처럼 보이는 금액
```

합산의 근거도 명시합니다. ES 합산은 `E[ΣX]=ΣE[X]` 로 **상관과 무관하게** 성립하므로 단순 합이
옳습니다. 가중 BBP 는 "예산환율을 넘길 것으로 기대되는 **금액의 비중**"이며,
"한 건이라도 넘을 확률"(`1−Π(1−pᵢ)`)이 **아닙니다** — 그건 독립을 가정해야 하는데 같은 통화의
연속 만기는 강하게 상관돼 성립하지 않습니다.

## 6. 한계 (알면서 남겨둔 것)

- **감사로그**: 해시체인은 *레코드 변경*을 잡지만 SQLite 파일 통째 교체는 못 막습니다.
  운영에는 WORM 스토리지 또는 외부 앵커링(체인 헤드 주기 공증)이 필요합니다.
- **인증**: 자체 IdP 입니다. KB 신원 연결은 KB 측 클라이언트 발급이 선행되어야 합니다.
- **OCR**: 이번 범위에서 제외했습니다. 데모의 OCR 은 여전히 시연이며 그렇게 표기돼 있습니다.
- **알림 발송**: 규칙 정의·평가·쿨다운은 실제로 동작하지만 **발송 채널이 없습니다.**
  문자·이메일·앱푸시는 행내 발송 인프라가 필요합니다. 평가 결과는 '발송 대기'로만 남습니다.
- **알림 구독·거래 저장**: 프로세스 메모리입니다(감사로그와 달리 파일 영속화 전).
  서버를 재시작하면 사라집니다.
- **리포트 PDF**: 미구현. `fpdf2` 는 있으나 한글 출력에 TTF 임베딩이 필요하고, 데모 폰트는
  woff2 서브셋이라 변환 도구가 더 필요합니다. 가치 대비 비용이 커서 남겨뒀습니다.
- **정책자금 매칭**: 미구현. 공고 데이터가 시시각각 바뀌어, 실연동 없이 만들면
  낡거나 지어낸 공고를 보여주게 됩니다.
